# YggTunnel

**Русский** · [English](README.md)

Проект для туннелирования трафика через mesh-сеть Yggdrasil. Локальный SOCKS5-прокси (sslocal-rust) передаёт зашифрованный трафик по Yggdrasil на удалённый ssserver-rust, который обеспечивает выход в обычный интернет.

```
           КЛИЕНТ                                         СЕРВЕР
┌───────────────────────────┐                   ┌────────────────────────┐
│    Приложение на хосте    │                   │   В обычный интернет   │
│            │              │                   │            ▲           │
│            ▼              │                   │            │           │
│      sslocal-rust         │                   │            │           │
│   SOCKS5 127.0.0.1:1080   │                   │   ssserver-rust:8388   │
│            │              │                   │            ▲           │
│            ▼              │ Yggdrasil network │            │           │
│      Yggdrasil node    ──────────────────────────>  Yggdrasil node     │
└───────────────────────────┘                   └────────────────────────┘
```

## Быстрый старт

### 1. На сервере

```sh
git clone https://github.com/minbbb/YggTunnel
cd YggTunnel
cp .env.example .env

# сгенерируйте два секрета и подставьте их в .env
openssl rand -hex 32   # -> SS_PASSWORD
openssl rand -hex 32   # -> YGG_GROUP_PASSWORD
```

Возьмите два-три публичных пира и подставьте их в .env в параметр YGG_PEERS.
Пиры можно взять отсюда https://publicpeers.neilalexander.dev/

Запускаем

```
docker compose up -d
```

Узнайте адрес сервера в сети Yggdrasil - он понадобится клиенту:

```sh
chmod a+x ./scripts/get-server-address.sh
./scripts/get-server-address.sh
# example: 200:1a2b:3c4d:5e6f:7a8b:9abc:def0:1234
```

Адрес выводится из приватного ключа узла в volume `ygg-state`, поэтому он не
меняется при перезапусках и изменится только если удалить этот volume.

### 2. На клиенте

```sh
git clone https://github.com/minbbb/YggTunnel
cd YggTunnel
cp .env.example .env
```

Заполните `.env`:

- `SS_PASSWORD` и `YGG_GROUP_PASSWORD` - те же значения, что на сервере
- `YGG_SERVER_ADDR` - адрес, напечатанный `get-server-address.sh`
- `YGG_PEERS` - два-три живых публичных пира.

```sh
docker compose -f docker-compose.client.yml up -d
```

### 2б. (опционально) Настройка допустимых нод

Получите Yggdrasil-адрес **клиента**

```sh
COMPOSE_FILE=docker-compose.client.yml ./scripts/get-server-address.sh
# example: 201:1a2b:3c4d:5e6f:7a8b:9abc:def0:1234
```

впишите его в `YGG_CLIENT_ADDR` в
`.env` **сервера**, затем перезапустите сервер:

```sh
docker compose up -d
```

Теперь сервер будет принимать подключения только с этого адреса.

Проверить что адрес применился можно командой

```
docker compose exec yggdrasil ip6tables -S INPUT | grep 8388
# -A INPUT -s 201:1a2b:3c4d:5e6f:7a8b:9abc:def0:1234/128 -i tun0 -p tcp -m tcp --dport 8388 -j ACCEPT
# -A INPUT -p tcp -m tcp --dport 8388 -j DROP
```

Чтобы добавить несколько адресов, напишите их через запятую. Если адрес клиента
заранее неизвестен или постоянно меняется, задайте `YGG_CLIENT_ADDR=any`.

### 3. Проверка

Для проверки можно сделать запрос на клиенте:

```bash
curl -x socks5h://127.0.0.1:1080 https://api.ipify.org
```

Вернётся **публичный IP сервера**.

> Обратите внимание на `socks5h` (домен резолвится через прокси - на стороне
> сервера). С `socks5` (без `h`) домен резолвится локально системным
> резолвером клиента и через туннель не пойдёт.

На сервере проверьте активность туннеля через вебконсоль
(`http://localhost:7070` после SSH-проброса, см. выше → I2P tunnels).

### 4. Подключение

Чтобы использовать, направте ваш браузер или другое приложение на SOCKS5 `127.0.0.1:1080`.

## Настройка

Всё в `.env`, аннотированная версия - `.env.example`.

| Переменная           | Где         | Значение                                                                                                                    |
| -------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| `SS_PASSWORD`        | обе стороны | Пароль Shadowsocks. Должен совпадать.                                                                                       |
| `SS_METHOD`          | обе стороны | Шифр, по умолчанию `aes-256-gcm`. Должен совпадать.                                                                         |
| `SS_SERVER_PORT`     | обе стороны | Порт на адресе Yggdrasil. Должен совпадать.                                                                                 |
| `SS_LOCAL_PORT`      | клиент      | Порт SOCKS5 на хосте, по умолчанию `1080`.                                                                                  |
| `YGG_GROUP_PASSWORD` | обе стороны | Пароль закрытого оверлея. Должен совпадать.                                                                                 |
| `YGG_SERVER_ADDR`    | клиент      | Адрес сервера в сети Yggdrasil.                                                                                             |
| `YGG_CLIENT_ADDR`    | сервер      | Кто может достучаться до порта Shadowsocks: адреса через запятую либо `any` без фильтра. Обязательна, пустой быть не может. |
| `YGG_PEERS`          | обе стороны | Пиры через запятую. Обязательна, значения по умолчанию нет: без неё узел вообще не может выйти в сеть. См. ниже.            |
| `YGG_VERSION`        | обе стороны | Релиз Yggdrasil для сборки, `0.5.14`.                                                                                       |
| `YGG_IF_MTU`         | обе стороны | MTU TUN, upstream-значение `65535`.                                                                                         |
| `SS_IMAGE_TAG`       | обе стороны | Тег образа shadowsocks-rust, `v1.25.0`.                                                                                     |

Entrypoint перерисовывает конфигурацию при каждом старте, поэтому после правки
`.env` достаточно `docker compose up -d` - обычный `restart` тоже подойдёт.
Пересборка нужна только при смене `YGG_VERSION`, Dockerfile или `entrypoint.sh`
(`./scripts/build-image.sh`).

### Выбор пиров

Параметр `YGG_PEERS`. Два ваших узла не пирятся друг с другом, они находят себя через
DHT, поэтому узел без пиров не доходит до сети и туннель не поднимается никогда.

Возьмите строки подключения публичных пиров и вставьте их через запятую:

```sh
YGG_PEERS=tls://a.example.org:1338?key=00000000...b9be63ce693e18a,tls://b.example.org:1338?key=000000d8...1e4644ae
```

Длинный список вписывается в двойные кавычки и разбивается на несколько строк.
У сервера и клиента списки могут различаться.

Пириться стоит только с узлами, которые **географически близки**. Задержка и
пропускная способность всего туннеля определяются первым хопом.

Проверьте их через `./scripts/yggctl.sh getPeers`, когда узел уже поднялся: если
туннель так и не работает, первое, на что стоит смотреть, - есть ли вообще пиры в
состоянии `Up`, см. «Диагностика» ниже.

Пир, у которого есть только `AAAA`-запись, недоступен из контейнера на хосте без
IPv6 и даёт в логе узла и в `getPeers` `connect: network is unreachable`. Это
шум, а не сбой: уберите его, дайте хосту IPv6 и не обращайте внимания, пока
два-три пира в состоянии `Up`.

## Вспомогательные скрипты

| Скрипт                            | Назначение                                                                                                                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `./scripts/get-server-address.sh` | Печатает Yggdrasil-адрес узла. Работает и при остановленном узле, если тот уже запускался. Учитывает `COMPOSE_FILE`, поэтому на клиенте печатает адрес клиента.                 |
| `./scripts/yggctl.sh <команда>`   | Выполняет `yggdrasilctl` на узле: `getSelf`, `getPeers`, `getSessions`, `getPaths`. По умолчанию `list`, который печатает все доступные команды. Тоже учитывает `COMPOSE_FILE`. |
| `./scripts/build-image.sh`        | Собирает закреплённый образ Yggdrasil. `PLATFORMS=linux/amd64,linux/arm64` для multi-arch.                                                                                      |

`getPaths` полезен, когда туннель кажется медленным: он печатает
последовательность хопов между узлами. При схеме «только через DHT» она длинная
и меняется по мере перестроения путей в сети - это нормально.
